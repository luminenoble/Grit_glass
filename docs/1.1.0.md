# 1.1.0 设计

本文是 1.1.0 的功能设计，尚未实现。实现后把落地的部分并入 [项目概览.md](项目概览.md)，再删除本文。本文只定功能、数据和排布规则，具体的视觉设计后续再定。

## 1. 目标

1. 很多任务没有明确的 DDL，但得在某段时间内完成。
2. 不想给任务分阶段，常常一次做完好几个阶段，有时又在一个阶段卡很久。
3. 一直挂着的任务会被渐渐忽略，有时又让人莫名焦虑。

思路：

- 任务有 DDL 时，DDL 就是限制；没有 DDL 时，“距上次改动多久”给一个软提示。
- 按四象限理解每个任务：
  - **紧急度**由 DDL 决定，用卡片大小表示。
  - **重要度**由 `priority` 决定，用颜色深浅表示。
- 完成的任务立即归档，Task 页只留未完成的。

## 2. 导航

底部导航改为 **Task / 总览 / Setting**。

- **Task**：现有的类别和任务列表，以及编辑功能，不显示已完成任务（§6）。
- **总览**：页内可以在两个视图之间切换，默认是“任务墙”。
  - **任务墙**：未完成任务按紧急度和重要度排布（§4）。
  - **已完成**：归档的任务（§6）。
- **Setting**：新增的设置项见 §7。

## 3. 数据

### 3.1 数据库（Room `SCHEMA_VERSION` 1 → 2）

| 对象 | 改动 |
| --- | --- |
| Task | 新增 `deadline: LocalDate?`，按天计，可以为空。 |
| Task | 新增 `priority`：`LOW` / `NORMAL` / `HIGH`，存为 0 / 1 / 2，默认 `NORMAL`。迁移时全部设为 `NORMAL`。 |
| Task | 新增 `lastTouchedAt: Instant`。迁移时取 `updatedAt`。 |
| Task | 新增 `completedAt: Instant?`。完成时写入，取消完成时清空。迁移时，已完成的任务取 `updatedAt`。 |
| Task | 新增 `hiddenUntil: LocalDate?`，表示挂起到哪一天。 |
| Task | 新增 `isSomeday: Boolean`，表示“以后再说”。 |
| Section | `completedOn` 改为布尔值 `isCompleted`，不再记录完成日期。迁移时 `completedOn != null` 的记为已完成。 |
| Category | 移除 `hideCompleted`。 |

**“动过”**：以下操作会更新 `lastTouchedAt`。只打开查看不算。

- 勾选或取消 Section；
- 修改标题、内容或 Section；
- 加入 Today；
- 修改 DDL 或优先级。

**`HIGH` 永不失效**：`HIGH` 任务不参与任何因为“久没动”触发的衰减（§5）。它离开当前位置，只有三种情况：手动完成、手动改优先级、手动挂起。

### 3.2 备份（格式独立，升到 v2）

- 导出 `format = "grit_glass"`、`formatVersion = 2`，包含 §3.1 的全部字段。备份仍不含本机设置。
- 导入时同时接受 v2，以及旧的 `grit_rhine` v1（包括 Grhinet 导出的文件）。v1 的字段按 §3.1 的迁移规则转换：

  | v1 字段 | 转换为 |
  | --- | --- |
  | Section 的 `completedOn` | `isCompleted` |
  | Category 的 `hideCompleted` | 忽略 |
  | （v1 中没有） | `priority` 取 `NORMAL` |
  | `updatedAt` | `lastTouchedAt` |
  | 已完成任务的 `updatedAt` | `completedAt` |

- Grhinet 不再能导入 Grit Glass 的备份，两个仓库的备份代码从此分开维护。
- 导入的流程不变：先校验，展示数量，用户确认后在一个事务内整库替换。

## 4. 任务墙

一面竖向滚动的卡片墙，没有坐标轴。阅读顺序就是优先顺序：从上到下、从左到右。

### 4.1 网格

- 4 列网格，行单位高 48 dp，间距 8 dp，左右留白 16 dp。在 360 dp 宽的屏幕上，每列约 76 dp。
- 宽屏布局为 8 列，单位尺寸不变。
- 每张卡片占整数个格子。

### 4.2 大小：紧急度

剩余天数 = `deadline` − 今天。三个阈值 `a < b < c` 由用户在设置中自定义，默认 1 / 7 / 30。

| 档位 | 条件 | 占格（列 × 行） | 360 dp 屏上约 |
| --- | --- | --- | --- |
| XL | 已过期，或剩余 ≤ a 天 | 4 × 2 | 328 × 104 dp |
| L | 剩余 a+1 到 b 天 | 2 × 2 | 160 × 104 dp |
| M | 剩余 b+1 到 c 天 | 2 × 1 | 160 × 48 dp |
| S | 剩余 > c 天，或没有 DDL | 1 × 1 | 76 × 48 dp |

- 档位在每天第一次计算时确定，一天之内不会因为时间推移而跳动。
- 档位按绝对天数划分，不按任务之间的相对排名。
- `isToday` 的任务至少按 L 档显示。
- **已过期**的任务按 XL 显示，左侧有一条细标记，不标红，也不写“逾期”。卡片上提供三个选择：设新 DDL、去掉 DDL、放弃（删除）。
- **标题**超出卡片时用省略号截断。字号由设置里的“任务墙字号”决定，各档卡片的格子大小不随字号变化。

### 4.3 深浅：重要度

用“减淡”表示重要度。减淡的意思是把颜色向卡片的纸面色混合。每个渐变色标分别混合。

| 优先级 | 减淡比例 |
| --- | --- |
| `HIGH` | 0，原色 |
| `NORMAL` | 35% |
| `LOW` | 60% |

减淡作用在哪些部分，由设置里的“重要度显示”决定：

| 选项 | 作用范围 |
| --- | --- |
| 标题与边框（默认） | 任务标题文字、类别色边框。卡片底色统一为纸面。 |
| 标题、边框与底色 | 除上面两项外，底色也用类别色淡染。淡染强度：`HIGH` 0.24、`NORMAL` 0.12、`LOW` 0.06。 |

现有规则是颜色原样显示、不做对比度修正。因此 `LOW` 任务如果本来就用浅色标题，减淡后可能看不清，需要在实际配色下检查。

### 4.4 排序

所有可见任务按以下键依次排序：

1. 档位：XL → L → M → S。
2. 有 DDL 的在前，没有的在后。实际只影响 S 档。
3. 优先级：`HIGH` → `NORMAL` → `LOW`。
4. 有 DDL 的，按 `deadline` 从早到晚；没有 DDL 的，按 `lastTouchedAt` 从近到远，越久没动越靠后。
5. 任务 ID，保证排序稳定。

先按档位排，是为了让同样大小的卡片挨在一起，排得更密。代价是：`HIGH` 的 M 档任务会排在 `LOW` 的 L 档任务之后。这种情况下，重要度只能靠颜色深浅体现。

### 4.5 排布算法

按 §4.4 的顺序逐个放卡片，行优先、密集填充，等价于 CSS `grid-auto-flow: row dense`：

1. 维护一张占用表，每行 4 格。
2. 取下一张卡片，从第一个空位开始，从上往下、从左往右，找到第一个能放下它的位置放进去。
3. **回填限制**：放进空洞的卡片，在排序上与空洞前一张卡片相距不能超过 4 位。没有符合条件的卡片，就让空洞留着。

大卡片排在前面，所以大多数行都能刚好填满：XL 独占一行，L 和 M 两张一行，S 四张一行。空洞只出现在档位交界处。例如 L 的数量为奇数时，最后一张 L 右侧会空出 2 × 2，由紧随其后的 M 或 S 回填。

### 4.6 分区与附加信息

- S 档中，有 DDL 和没有 DDL 的任务之间插入一行“没有 DDL”分隔标签，占满整行，高 24 dp。
- 分隔线以下的卡片显示距上次改动的天数，如“12 天”。分隔线以上的卡片显示剩余天数。都用中性小字，不变色。

### 4.7 不出现在任务墙上的任务

- 已完成的任务（已归档）。
- `hiddenUntil` 在未来的任务，到期后自动回来。
- `isSomeday` 的任务，只在“以后再说”页显示。

任务墙默认显示全部类别，靠边框颜色区分。可以按类别筛选，筛选后排布规则不变。

## 5. 衰减与“沉底即决定”

没有 DDL 的 `NORMAL` 和 `LOW` 任务，越久没动就排得越靠后（§4.4）。超过下表的天数没动时，卡片原位出现一条可以忽略的提示，三个选择：改写成更小的任务、转入“以后再说”、放弃。

| 优先级 | 天数 |
| --- | --- |
| `LOW` | 30 天 |
| `NORMAL` | 60 天 |
| `HIGH` | 不衰减 |

这与操作系统调度里的“老化”方向相反。这里让久没动的任务下沉，是因为久没动往往说明它没那么重要；真正不能忘的任务，应设为 `HIGH`。

## 6. 完成与归档

- **任务完成即归档。** 勾选完成后，任务立即从 Task 页和任务墙消失，同时弹出 Snackbar“已归档 · 撤销”。
- **排序不变。** 归档的任务保留原来的 `orderIndex`，Task 页只是跳过它们，所以同一类别内的排序仍然连续。在“已完成”视图里取消完成，任务会回到原类别的原位置。
- **“已完成”视图**：所有归档任务按 `completedAt` 从新到旧，用同样大小的卡片在 4 列网格上依次排列，每张 2 × 1，不分档位。颜色规则与任务墙相同。点按卡片可以进入详情。
- **“删除已完成”**：保留这个功能，作用于全部归档任务，需要二次确认。按钮放在哪里，由后续的 UI 设计决定。
- **`hideCompleted`**：随归档一起移除（§3.1）。

## 7. 其他

- **Today 每日清零**：每天第一次打开 app 时，前一天没完成的 Today 任务静默退回原类别，不计数，也不标逾期。
- **挂起**：可以选明天、下周一、一个月后，或者指定日期。挂起期间，任务不出现在 Task 页和任务墙上。
- **以后再说**：不带日期，单独一页。入口位置由后续的 UI 设计决定。
- **新增设置项**：
  - 档位阈值 a / b / c：正整数，必须满足 a < b < c。
  - 任务墙字号：小 / 中 / 大。
  - 重要度显示：标题与边框 / 标题、边框与底色。
- **小组件**：不再开发，本轮不做功能改动。但 `hideCompleted` 移除后，小组件统一不显示已完成任务，与归档保持一致。

## 8. 本轮不做

- 卡住诊断向导
- 自动切检查点
- 连续天数
- 强制填写“下一步”
- 固定的“本周 / 本月”分桶
- 二维坐标平面
- 小组件新功能
- 视觉设计
