# 开发与发布

构建、测试、预览和发版的现行做法。流程变化时更新本文。

## 1. 环境（本机 WSL2）

| 项 | 位置 / 说明 |
| --- | --- |
| JDK | 项目要求 Java 21：`export JAVA_HOME=~/jdk-21`（WSL 默认的 17 不行） |
| Android SDK | `~/Android/Sdk`；build-tools `37.0.0`（`zipalign`、`apksigner`、`aapt2`） |
| ADB | 用 Windows 的 `/mnt/d/professionalTools/AndroidStorage/sdk/platform-tools/adb.exe`，Linux 的 adb 看不到模拟器。安装时 APK 先复制到 `/mnt/d/wsl-share` 下，再传 Windows 路径 |
| 模拟器 | AVD `grhinet-visual-api36`（API 36，1080×2400，420 dpi） |
| Windows 侧 JDK | `D:\compilerStorage\jdk\jdk-24.0.2`（运行桌面端 jar；在 Windows 上打 MSI / EXE 也用它） |
| 用户参考图 | 放在仓库的 `tmp/`，不提交 |

## 2. 构建与测试

```sh
./gradlew :androidApp:assembleFossDebug
./gradlew :androidApp:testFossDebugUnitTest              # 单元测试
./gradlew :androidApp:connectedFossDebugAndroidTest      # 数据库测试，需设备
./gradlew :shared:ui:compileKotlinJvm :webDemo:compileKotlinJvm :webDemo:compileKotlinWasmJs
./gradlew :desktopApp:test                               # 局域网同步端到端、回滚快照、SnapshotTaskRepo、SkSL 透镜
./gradlew :androidApp:lintFossRelease
```

- `:desktopApp:test` 里还有两个默认跳过的手动检查：`GRIT_SCREENSHOTS=<目录>` 时 `Screenshots` 把任务墙、手机临期清单和两端的 LAN Sync 页离屏渲染成 PNG；`GRIT_LAN_SERVE=<秒> GRIT_LAN_OUT=<文件> GRIT_LAN_HOST=10.0.2.2 GRIT_LAN_LIBRARY=<tasks.json>` 时 `ServeForDevice` 在 WSL 里开一个同步服务供模拟器连接（模拟器经 `10.0.2.2` → Windows 回环 → WSL 转发访问），配对链接写进输出文件，可用 `adb.exe shell "am start -a android.intent.action.VIEW -d '<链接>' io.github.luminenoble.gritglass.debug"` 打开。

- 改动 `shared/` 的公共代码后，JVM 与 Wasm 也要编译通过，`:desktopApp` 也要编译通过；设置接口变化时同步 Android 实现与 JVM / Wasm 桩。`expect` 声明（如 `glassLensEffect`）在三个平台都要有实现。
- 数据库 schema 变化：提高 `TaskDatabase.SCHEMA_VERSION`，加迁移并提交导出的 `androidApp/schemas/.../N.json`。只增删列、不动已有值时用 `@AutoMigration`；要转换已有值时在 `Migrations.kt` 手写 `Migration`，在 `TaskDbFactory` 里 `addMigrations`，建表语句照抄导出的 `N.json`（把表名换成临时名），否则 Room 启动时校验 schema 会失败。迁移用第 4 节的办法在模拟器上验证：换入上一版 schema 的测试库，启动后取回数据库核对。
- 全仓 Spotless 在 WSL 路径下常失败，一般不跑。
- 用户说明“验证由我在设备上完成”时，只做单元测试、编译和必要的模拟器截图，跳过设备测试与 Lint，并在汇报里写明跳过了什么。

## 3. 桌面端

```sh
./gradlew :desktopApp:run                    # 在当前系统上运行（WSL 里走 WSLg）
./gradlew :desktopApp:windowsJar             # desktopApp/build/windows/GritGlass-<版本>.jar
```

- `windowsJar` 是带 Windows（和当前系统）本地库的单个 jar，在 WSL 里就能打，Windows 上装有 Java 21+ 即可运行：`javaw --enable-native-access=ALL-UNNAMED -jar GritGlass-<版本>.jar`。
- 免安装版（带运行时的 `GritGlass.exe` 文件夹，不需要 WiX）可以在 WSL 里调用 Windows JDK 的 jpackage 生成，`<输入目录>` 里只放上面的 jar：

  ```sh
  cmd.exe /c 'D:\compilerStorage\jdk\jdk-24.0.2\bin\jpackage.exe --type app-image --name GritGlass --app-version 1.1.<versionCode> --input <输入目录> --main-jar GritGlass-<版本>.jar --main-class com.shub39.grit.desktop.MainKt --icon <仓库>\desktopApp\icon.ico --java-options "--enable-native-access=ALL-UNNAMED" --java-options "-Dfile.encoding=UTF-8" --dest <输出目录>'
  ```

- 安装包只能在 Windows 上打（jpackage + WiX，Compose 插件会自动下载 WiX）：在 Windows 终端里 `gradlew.bat :desktopApp:packageMsi`（或 `packageExe`；Gradle 会配置整个工程，所以 Windows 侧也要能找到 Android SDK，尚未实测），产物在 `desktopApp\build\compose\binaries\main\`，自带运行时，按用户安装，开始菜单分组“Grit Glass”。MSI 版本号是 `主.次.versionCode`（例：1.1.1.2 → `1.1.1112`），保证升级时递增；`upgradeUuid` 固定不能改。
- 试用时可用 `GRIT_GLASS_HOME=<目录>` 把数据放到别处，不碰 `%APPDATA%\GritGlass`。

## 4. 模拟器测试数据

Debug 包（`io.github.luminenoble.gritglass.debug`）可以直接换入一份测试库：先启动一次再停止，然后

```sh
adb.exe push 'D:\wsl-share\seed.db' /data/local/tmp/seed.db
adb.exe shell "run-as io.github.luminenoble.gritglass.debug sh -c \
  'rm -f databases/grit_glass_database*; cp /data/local/tmp/seed.db databases/grit_glass_database'"
```

测试库的三张表要与对应版本的 `schemas/.../N.json` 一致，`room_master_table` 的 identity hash 要与其中的 `identityHash` 相同，`user_version` 为 N。换入旧版本的库，启动时就会跑迁移；之后停掉 app，用 `adb.exe exec-out run-as … cat databases/grit_glass_database`（连同 `-wal`、`-shm`）取回来核对。测试库和截图只放在会话临时目录，不入库。

## 5. 发版

版本号 `X.Y.Z` 对应 `versionCode = XYZ0`（例：1.0.0 → 1000），四段的 `X.Y.Z.W` 对应 `XYZW`（例：1.1.1.2 → 1112）。分支为 `master`。

1. **改版本**：根目录 `gradle.properties` 的 `grit.versionName` / `grit.versionCode`（Android 与桌面端共用）。
2. **写更新内容**：
   - `CHANGELOG.md` 顶部加一节（英文）；构建时 `generateChangelog` 据此生成应用内“更新内容”读取的 `androidApp/src/main/assets/changelog.json`，一并提交；
   - `README.md` 中的版本号与下载链接；
   - 行为有变化时更新 [项目概览.md](项目概览.md)。
3. **构建与签名**：

   ```sh
   ./gradlew :androidApp:assembleFossRelease
   BT=~/Android/Sdk/build-tools/37.0.0
   IN=androidApp/build/outputs/apk/foss/release/androidApp-foss-release-unsigned.apk
   $BT/zipalign -c -P 16 -v 4 $IN | tail -1                 # 16 KB 对齐
   $BT/apksigner sign --ks ~/.android/debug.keystore --ks-key-alias androiddebugkey \
     --ks-pass pass:android --key-pass pass:android --out GritGlass-X.Y.Z-foss.apk $IN
   $BT/apksigner verify --print-certs -v GritGlass-X.Y.Z-foss.apk  # v3，SHA-256 901fbd15…
   sha256sum GritGlass-X.Y.Z-foss.apk > SHA256SUMS.txt
   ```

   桌面端：`./gradlew :desktopApp:windowsJar` 得到 `GritGlass-X.Y.Z.jar`；需要安装包时在 Windows 上 `gradlew.bat :desktopApp:packageMsi`（第 3 节）。

   签名必须沿用这把证书（SHA-256 以 `901fbd15` 开头），否则用户无法覆盖升级。签名产物放在仓库外。
4. **验证**：至少在模拟器上从上一版覆盖安装并启动；schema 变化时确认迁移后数据保留。
5. **提交、打标签、推送**：提交（不含 `tmp/`），`git tag X.Y.Z`，推送 `master` 和标签到 `origin`（`luminenoble/Grit_glass`）。
6. **GitHub Release**：`gh release create X.Y.Z GritGlass-X.Y.Z-foss.apk SHA256SUMS.txt --repo luminenoble/Grit_glass --title "Grit Glass X.Y.Z" --notes-file notes.md --verify-tag`。说明用中文，写变化、覆盖升级说明和验证范围。应用内的检查更新读取这个仓库的最新 Release。
7. 按 `AGENTS.md`：不创建 issue 或 PR。
