# 开发与发布

构建、测试、预览和发版的现行做法。流程变化时更新本文。

## 1. 环境（本机 WSL2）

| 项 | 位置 / 说明 |
| --- | --- |
| JDK | 项目要求 Java 21：`export JAVA_HOME=~/jdk-21`（WSL 默认的 17 不行） |
| Android SDK | `~/Android/Sdk`；build-tools `37.0.0`（`zipalign`、`apksigner`、`aapt2`） |
| ADB | 用 Windows 的 `/mnt/d/professionalTools/AndroidStorage/sdk/platform-tools/adb.exe`，Linux 的 adb 看不到模拟器。安装时 APK 先复制到 `/mnt/d/wsl-share` 下，再传 Windows 路径 |
| 模拟器 | AVD `grhinet-visual-api36`（API 36，1080×2400，420 dpi） |
| 用户参考图 | 放在仓库的 `tmp/`，不提交 |

## 2. 构建与测试

```sh
./gradlew :androidApp:assembleFossDebug
./gradlew :androidApp:testFossDebugUnitTest              # 单元测试
./gradlew :androidApp:connectedFossDebugAndroidTest      # 数据库测试，需设备
./gradlew :shared:ui:compileKotlinJvm :webDemo:compileKotlinJvm :webDemo:compileKotlinWasmJs
./gradlew :androidApp:lintFossRelease
```

- 改动 `shared/` 的公共代码后，JVM 与 Wasm 也要编译通过；设置接口变化时同步 Android 实现与 JVM / Wasm 桩。`expect` 声明（如 `glassLensEffect`）在三个平台都要有实现。
- 数据库 schema 变化：提高 `TaskDatabase.SCHEMA_VERSION`，加 `@AutoMigration`，提交导出的 `androidApp/schemas/.../N.json`，并补迁移测试。
- 全仓 Spotless 在 WSL 路径下常失败，一般不跑。
- 用户说明“验证由我在设备上完成”时，只做单元测试、编译和必要的模拟器截图，跳过设备测试与 Lint，并在汇报里写明跳过了什么。

## 3. 模拟器测试数据

Debug 包（`io.github.luminenoble.gritglass.debug`）可以直接换入一份测试库：先启动一次再停止，然后

```sh
adb.exe push 'D:\wsl-share\seed.db' /data/local/tmp/seed.db
adb.exe shell "run-as io.github.luminenoble.gritglass.debug sh -c \
  'rm -f databases/grit_glass_database*; cp /data/local/tmp/seed.db databases/grit_glass_database'"
```

测试库的三张表要与 `schemas/.../1.json` 一致，`room_master_table` 的 identity hash 要与其中的 `identityHash` 相同，`user_version` 为当前 schema 版本。测试库和截图只放在会话临时目录，不入库。

## 4. 发版

版本号 `X.Y.Z` 对应 `versionCode = XYZ0`（例：1.0.0 → 1000）。分支为 `master`。

1. **改版本**：`androidApp/build.gradle.kts` 的 `appVersionCode` / `appVersionName`。
2. **写更新内容**：
   - `CHANGELOG.md` 顶部加一节（英文）；构建时 `generateChangelog` 据此生成应用内“更新内容”读取的 `androidApp/src/main/assets/changelog.json`，一并提交；
   - `README.md` 中的版本号与下载链接；
   - 行为有变化时更新 [项目概览.md](项目概览.md)。
3. **构建与签名**：

   ```sh
   ./gradlew :androidApp:assembleFossRelease
   BT=~/Android/Sdk/build-tools/37.0.0
   IN=androidApp/build/outputs/apk/foss/release/androidApp-foss-release-unsigned.apk
   $BT/zipalign -c -P 16 -v 4 $IN | tail -1                 # 16 KB 对齐
   $BT/apksigner sign --ks ~/.android/debug.keystore --ks-key-alias androiddebugkey \
     --ks-pass pass:android --key-pass pass:android --out GritGlass-X.Y.Z-foss.apk $IN
   $BT/apksigner verify --print-certs -v GritGlass-X.Y.Z-foss.apk  # v3，SHA-256 901fbd15…
   sha256sum GritGlass-X.Y.Z-foss.apk > SHA256SUMS.txt
   ```

   签名必须沿用这把证书（SHA-256 以 `901fbd15` 开头），否则用户无法覆盖升级。签名产物放在仓库外。
4. **验证**：至少在模拟器上从上一版覆盖安装并启动；schema 变化时确认迁移后数据保留。
5. **提交、打标签、推送**：提交（不含 `tmp/`），`git tag X.Y.Z`，推送 `master` 和标签到 `origin`（`luminenoble/Grit_glass`）。
6. **GitHub Release**：`gh release create X.Y.Z GritGlass-X.Y.Z-foss.apk SHA256SUMS.txt --repo luminenoble/Grit_glass --title "Grit Glass X.Y.Z" --notes-file notes.md --verify-tag`。说明用中文，写变化、覆盖升级说明和验证范围。应用内的检查更新读取这个仓库的最新 Release。
7. 按 `AGENTS.md`：不创建 issue 或 PR。
