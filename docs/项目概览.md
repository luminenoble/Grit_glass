# 项目概览

Grit Glass 的现行结构，对应 1.1.0（2026-11-16）。构建与发布见 [开发与发布.md](开发与发布.md)。改动这里描述的内容时，在同一个提交里更新本文。

## 1. 应用

纯待办应用，从 Grhinet 6.2.4 分出，去掉了 Rhine 场景和插图；Grhinet 本身在 [luminenoble/Grit](https://github.com/luminenoble/Grit) 单独维护。两者都基于上游 [Grit](https://github.com/shub39/Grit)（GPL-3.0）。

- 显示名 Grit Glass，`applicationId` 为 `io.github.luminenoble.gritglass`，可与 Grhinet 同时安装。Kotlin 包名和文件路径与 Grhinet 保持一致，方便两个仓库互相 `cherry-pick` 共用部分的修复（本仓库的 `grhinet` remote 指向 Grhinet）。
- 底部导航：**Task / 总览 / Setting**。Task 是类别与任务列表，总览是任务墙、“以后再说”和已完成（第 4 节）。
- 已从上游移除且不恢复：Habit、统计栏目、AI 任务分解、动态取色与整体调色、深色主题。

| 项目 | 现状 |
| --- | --- |
| 语言 / UI | Kotlin 2.4、Compose Multiplatform 1.11.1、Material3 Expressive |
| 模块 | `:androidApp`（Room、DataStore、Glance 小组件、平台实现）、`:shared:core`（模型与接口）、`:shared:ui`（commonMain UI）、`:webDemo`（JVM / Wasm 演示桩，需保持可编译） |
| Android | minSdk 29、target / compile 37 |
| 主题 | 固定米色浅色主题 + 液态玻璃控件（见第 5 节） |

## 2. 数据

以 `Category → Task → Section` 组织。

| 对象 | 主要字段 |
| --- | --- |
| Category | `name`、`description`、`orderIndex`、`titleColor`、`createdAt/updatedAt` |
| Task | `categoryId`、`title`、`description`、`orderIndex`、`titleColor`、`isCompleted`（手动）、`isToday`、`reminder`、`deadline`（DDL，按天，可空）、`priority`（`LOW` / `NORMAL` / `HIGH`，存为 0 / 1 / 2，默认 `NORMAL`）、`lastTouchedAt`、`completedAt`、`hiddenUntil`（挂起到哪天）、`isSomeday`（以后再说）、时间戳 |
| Section | `taskId`、`title`（空则为 `unname`）、`content`、`orderIndex`、`isCompleted`、`titleColor`、时间戳 |

规则：

- ID 固定，不随排序改变；`orderIndex` 在同一父级内从 0 连续；新增一律尾插；移动和删除在事务内补齐排序。
- Section 的完成是布尔值，不记日期。Task 与 Section 的完成互不影响。已完成 Task 不触发提醒，重新打开时只恢复仍在未来的提醒。
- **完成即归档**：Task 完成时仓库写入 `completedAt`，取消完成时清空。归档的任务保留原来的 `orderIndex`，Task 页、任务墙和小组件只是跳过它，取消完成后回到原类别的原位置。
- **在场**（`Task.isActive`）：未完成、不是“以后再说”、`hiddenUntil` 不在未来。只有在场的任务出现在 Task 页（包括 Today）和任务墙上。挂起的任务到 `hiddenUntil` 当天自动回来；“以后再说”不带日期，要手动放回。
- **动过**（`touches`）：修改标题、内容、Section（包括勾选）、DDL、优先级，或加入 Today，仓库就把 `lastTouchedAt` 更新为当前时间。只打开查看、排序、完成、挂起、改颜色不算。
- **Today 每日清零**：每次显示 app 时，如果日期比 DataStore 里记的 `last_opened_on` 新，就清掉所有任务的 `isToday`（`clearToday`）。不算“动过”，不计数，也不标逾期。
- **颜色** `titleColor`：null 为默认；`#RRGGBB` 为纯色；2–5 个以逗号分隔为从左到右的渐变（如 `#C0392B,#1E6FD9`）。仓库写入、备份导入都校验格式（`shared/core/.../tasks/TaskRules.kt`）。颜色原样显示，不做对比度修正。

**数据库** `grit_glass_database`，Room，`SCHEMA_VERSION = 2`（`androidApp/.../tasks/data/database/`）：`categories`、`tasks`、`sections` 三表，外键级联。1 → 2 是手写迁移 `Migration1To2`（`Migrations.kt`），因为要转换已有的值：三张表各自重建后改名到位；`priority` 全部为 `NORMAL`，`lastTouchedAt` 取 `updatedAt`，已完成任务的 `completedAt` 取 `updatedAt`，Section 的 `completedOn != null` 记为已完成，Category 去掉 `hideCompleted`。schema 变化时提高版本并加迁移（见开发与发布）。

**备份**：`TaskBackup`（`shared/core/.../settings/backup/TaskBackup.kt`），JSON 中 `format = "grit_glass"`、`formatVersion = 2`，包含上表的全部字段，Section 嵌套在 Task 内。导入同时接受旧的 `grit_rhine` 版本 1（Grit Glass 1.0.x 和 Grhinet 导出的文件），先按数据库迁移的同一套规则改写成版本 2 再校验。Grhinet 不能导入 Grit Glass 的备份，两个仓库的备份代码分开维护。导入先校验（ID、引用、颜色、日期、连续排序）、展示数量，确认后在一个事务内整库替换；失败不改动现有数据。备份不含本机设置。

## 3. Task 页与 Setting

- Task 页：顶栏（切换完成状态、调整顺序）、类别托盘（今天、各类别、新增 / 编辑类别）、任务卡列表、右下角添加任务。只列在场的任务（第 2 节）；任务卡在标题下显示 DDL。
- 勾选完成后任务立即离开列表，导航胶囊上方出现玻璃提示“已归档 · 撤销”，停留 5 秒（`ArchiveToast`，Task 页和总览共用）。
- **切换完成状态**（顶栏“调整顺序”左边的对勾圆圈图标）：打开时每张任务卡右侧出现圆圈，点按任务卡即完成并归档；关闭时点按任务卡不做任何事，只能滚动列表，防止滑动时误触完成。它与“调整顺序”互斥（打开一个会关掉另一个），切换类别时两者都关闭。宽屏布局里每个类别面板的“调整顺序”旁各有一个，只管本面板。左侧详情按钮进入编辑，不受影响；长按拖动排序不变。
- 任务详情、新建任务、类别编辑是整页编辑器，用一份草稿，保存时整体提交，返回时有未保存提示。任务编辑器里有 DDL（按天选，可清除）、优先级（低 / 普通 / 高）、挂起（明天、下周一、一个月后、选日期）和“以后再说”。Section 列表有“调整顺序”切换：默认右侧为编辑图标，调整时为拖动手柄，也可输入目标序号。
- 颜色选择 `ColorPickerDialog`：纯色 / 渐变（至多 5 色）、色环与亮度、R/G/B 与 HEX 输入、复制粘贴（同时写入应用内与系统剪贴板，粘贴优先读系统剪贴板）。Category、Task、Section 表单共用 `TitleColorRow`。
- Setting：通知、小组件字号、启动页面（Task / 总览 / Setting）、24 小时制、任务墙（见下）、外观（字体、“降低透明度”）、备份、关于、更新内容、语言。
- 任务墙设置 `WallSettings`：卡片大小的三个天数阈值（正整数，必须 a < b < c，默认 1 / 7 / 30，不合法的输入不保存）、任务墙字号（小 / 中 / 大）、重要度显示（“标题与边框”或“标题、边框与底色”）。

## 4. 总览

代码：`shared/core/.../tasks/Wall.kt`（档位、排序、排布，纯函数）、`shared/ui/.../overview/`（`OverviewScreen`、`WallTile`、`TaskLens`、`CardTapKeys`）。

页内右上角的分段在三个视图间切换，默认是任务墙；下面的类别托盘可以只看一个类别，排布规则不变。

### 4.1 任务墙

一面竖向滚动的卡片墙，没有坐标轴。**大小是紧急度，深浅是重要度**，阅读顺序（从上到下、从左到右）就是优先顺序。只放在场的任务。

- **网格**：4 列，行高 48 dp，间距 8 dp，左右留白 16 dp；宽屏为 8 列，单位尺寸不变。每张卡片占整数个格子，格子大小不随字号变化。
- **档位**（`wallTier`）：剩余天数 = `deadline` − 今天，按绝对天数划分，所以一天之内不会跳动。阈值 a / b / c 来自设置。

  | 档位 | 条件 | 占格（列 × 行） |
  | --- | --- | --- |
  | XL | 已过期，或剩余 ≤ a 天 | 4 × 2 |
  | L | 剩余 a+1 到 b 天 | 2 × 2 |
  | M | 剩余 b+1 到 c 天 | 2 × 1 |
  | S | 剩余 > c 天，或没有 DDL | 1 × 1 |

  `isToday` 的任务至少按 L 档显示，右下角带一个小太阳。
- **排序**（`wallOrder`）：档位 → 有 DDL 的在前 → 优先级从高到低 → 有 DDL 的按 DDL 从早到晚，没有的按 `lastTouchedAt` 从近到远 → ID。
- **排布**（`packWall`）：按顺序逐张放到第一个放得下的位置，等价于 CSS `grid-auto-flow: row dense`。回填有限制：补进空洞的卡片，在排序上与空洞前一张卡片相距不超过 4 位，否则空洞留着。
- **“没有 DDL”分隔行**：S 档里有 DDL 和没有 DDL 的任务之间插一行标签（高 24 dp），两边分开排布，卡片不会越过这条线。线以上的卡片显示剩余天数（“明天”“3 天”），线以下显示距上次动过的天数（“12 天”“刚动过”），都是中性小字，不变色。
- **卡片**（`WallTile`）：不透明纸面，类别色做 1.5 dp 边框，标题用任务自己的颜色。单行卡片圆角 14 dp，双行 20 dp。标题放不下时用省略号截断；XL 卡片有空间时在标题下带一行内容，双行卡片左下角有日期和 Section 进度（“2/4”）。
- **重要度**：把颜色向纸面色混合来“减淡”，渐变的每个色标分别混合。`HIGH` 不减淡，`NORMAL` 35%，`LOW` 60%。作用于标题和边框；设置选“标题、边框与底色”时，底色再用类别色淡染（`HIGH` 0.24、`NORMAL` 0.12、`LOW` 0.06）。颜色不做对比度修正，浅色标题配 `LOW` 可能偏淡。
- **已过期**：按 XL 显示，左侧一条 3 dp 的墨色细标记，不标红，也不写“逾期”。卡片底部直接给三个选择：设新 DDL、去掉 DDL、放弃（删除，需确认）。
- **沉底**（`hasSunk`）：没有 DDL 的任务久没动就越排越靠后；`LOW` 超过 30 天、`NORMAL` 超过 60 天没动时，卡片换成已完成内容用的深米色 `#E3DCCE`，预览里问一句“它已经 N 天没动了，还要做吗？”，给三个选择：改小一点（进编辑器）、以后再说、放弃。可以不理会。`HIGH` 永不沉底，只会因为手动完成、改优先级或挂起而离开原位。

### 4.2 两个功能键与预览

- **功能键**（`CardTapKeys`）：浮在卡片上方右下角的玻璃胶囊，做法与导航胶囊相同（选中的是抬起的透镜并展开名字）。它决定点按卡片做什么：**预览**（默认）或**详情**（进入整页编辑器）。长按卡片做另一件事。三个视图共用这个选择。
- **预览**（`TaskLens`）：一片玻璃从卡片所在的位置胀开，盖在墙上，其余部分被一层 0.42 的纸面色压淡。它画在页面里而不是 `Dialog` 窗口里，所以能真的采样墙面：`Regular` 档，底色减到 0.48，卡片的颜色在玻璃后面化成一团团光晕。点玻璃外面或按返回收起。
- 预览里不进编辑器就能做的事：勾选 Section、完成、挂起（明天 / 下周一 / 一个月后 / 选日期）、转入“以后再说”，以及对过期和沉底任务的那三个选择。已完成的任务给“恢复为未完成”，“以后再说”的给“放回任务墙”，挂起中的给“现在就回来”。

### 4.3 以后再说、已完成

两个视图都用同样大小的卡片（2 × 1）依次排列，颜色规则与任务墙相同。

- **以后再说**：分“以后再说”（按 `lastTouchedAt` 从近到远）和“挂起中”（按回来的日期从早到晚，卡片上写日期）两组。
- **已完成**：全部归档任务按 `completedAt` 从新到旧，卡片上写完成日期。右上角“删除已完成”作用于全部归档任务，需要二次确认。

## 5. 液态玻璃

代码：`shared/ui/.../theme/LiquidGlass.kt`（材质、尺寸、采样）、`theme/GlassPress.kt`（按压）、`androidMain/.../theme/GlassLens.android.kt`（透镜着色器）、`components/glass/GlassComponents.kt`（按钮、开关、分段等）。

**原则**：玻璃只用于浮在内容上的控件；任务卡、设置行是不透明的纸面（`Content` 档）。玻璃靠光来成形：透镜边、高光边、形状外侧的暖褐阴影，底色很淡。按下时被光照亮，任何时候都不变暗。

| 档位 | 用途 | 底色（有采样 / 无采样） | 模糊 | 透镜边带 | 色散 |
| --- | --- | --- | --- | --- | --- |
| `Thin` | 导航胶囊、添加任务、图标按钮、类别芯片与托盘、分段、提示 | `#FBF8F3` 0.08 / 0.36 | 1.5 dp | 14 dp | 0.35 |
| `Regular` | 菜单、滚动后的顶栏、任务预览 | `#FBF8F3` 0.55 / 0.82 | 18 dp | 10 dp | 0 |
| `Thick` | 对话框、底部表单 | `#F2EDE5` 0.82 / 0.95 | 30 dp | 无 | 0 |
| `Content` | 任务卡、设置分组行 | 不透明 | 无 | 无 | 0 |

- 一个玻璃面由下到上：形状外侧的暖褐 `#5B4B3A` 阴影（模糊后裁掉形状内部，所以不会从下面把玻璃染灰）→ 背景采样（先模糊，再过透镜）→ 底色 → 顶部光泽 → 底部内侧聚光 → 左上最亮的高光边 → 外细线。
- **透镜**（Android 13+，AGSL `RuntimeShader`）：参考 Apple Liquid Glass 和 Kyant 的 AndroidLiquidGlass。用圆角矩形 SDF 求到边缘的距离，在宽 `bevel` 的边带里，玻璃表面按四分之一圆下落，采样点沿法线向内偏移 `bend·(1−√(1−x²))`（x 在边缘为 1，`bend = 1.25·bevel`）；红、蓝通道分别多 / 少偏移 `dispersion` 倍做色散；整体饱和度 ×1.25；边带按下落量提亮 0.22。着色器只编译一次，所有玻璃共用。
- Android 12 只有模糊没有透镜；Android 10–11、“降低透明度”（全部不透明）、独立窗口（`Dialog`、`Popup`、`ModalBottomSheet` 采样不到主窗口）都不采样，用无采样底色；Android 12 以下阴影改用平台阴影。
- **采样源**：`Modifier.glassSource` 每次绘制把内容记录进图层，采样它的玻璃不能画在它里面。紧凑布局里整个 `NavDisplay` 是导航胶囊的源，任务列表的 `Column` 是添加任务按钮的源，总览页的 `Column` 是功能键和任务预览的源。顶栏按钮和类别托盘在源内部，不采样。大片的 `Regular` 玻璃要求源把纸面背景也记录进去（`background` 写在 `glassSource` 之后）：否则记录下来的只有内容，模糊后是半透明的，下面清晰的内容会从玻璃里透出来。
- **浮动层**：紧凑布局里导航胶囊浮在页面上，测得的高度经 `LocalFloatingBarInset` 提供。任务列表、设置各页、整页编辑器把它加进底部内边距，内容可以一直滚到胶囊下面；添加任务按钮和总览的功能键放在它上方 16 dp。
- **尺寸** `GlassMetrics`：所有控件（图标按钮、文字按钮、类别芯片、导航项）高 44 dp，主操作 56 dp，托盘内边距 6 dp，图标 22 dp。
- **按压**：不用灰色状态层。`GlassPressIndication` 是全局 `LocalIndication`，从手指处向外泛光（90 ms 亮起、360 ms 退去），光在文字和图标下面；玻璃控件同时放大到 1.06。Material 组件自带的涟漪改为白色（`GlassRipple`）。键盘焦点显示为墨色描边。
- **状态**：选中（导航项、类别芯片、分段、打开的切换按钮）和主按钮 `Prominent` 是更亮更密的透镜 `#FFFDF9` 0.62，文字加粗，仍然透光；`Danger` 是透明玻璃配 `#9A3B30` 文字；开关打开为橄榄色 `#66704F`。
- 托盘里的图标按钮不单独成片（`inTray`），与未选中的芯片一样平放；单独的图标按钮是透明玻璃圆片。
- 玻璃上的次要文字用 `#57534B`，不要用 `mutedText #8C857A`（对比度不足）。

## 6. 小组件

Glance 任务小组件（RemoteViews，无法真模糊桌面）。背景和条目是 `layer-list` drawable（`widget_glass_bg`、`widget_glass_item(_done)`）模拟玻璃。

- 只显示未完成的任务，与归档一致。
- 每条任务是自有布局 `widget_task_row`：只有标题（一个带玻璃背景的 `TextView`），不显示步骤（Section）数，以 `AndroidRemoteViews` 整条嵌入，点击切换完成。不要把 `AndroidRemoteViews` 放进 Glance 带背景的容器里：Glance 会把它插到背景那一层，并丢掉同一容器里的其他子项。
- 桌面会把一条任务的视图复用给另一条任务，旧视图上设过的属性会留下来。所以每次绑定都要设全背景、内边距、字号、颜色和文字，不能只给部分任务设置某个属性（例如只在有步骤时显示一行），否则别的任务会带出上一条的内容和字号。
- Task 标题按存储的颜色显示，渐变也一样。Glance 的文字不支持渐变画笔，所以标题是 `TextView`，每个字带自己的 `ForegroundColorSpan`：按小组件实际宽度用 `StaticLayout` 排版（最多两行），取每个字的水平中点在最宽一行中的位置，在等距色标间插值（`widgets/WidgetTitleGradient.kt`）。效果与 Task 页横跨标题的渐变一致，只是逐字而非逐像素。
- 字号取自应用内设置（小 / 中 / 大），类别名与任务标题同号。在第一帧之前读出；不能以默认值起步，否则每次小组件会话开始都会先按“中”画一遍再跳到所选字号。`Content` 的字号参数没有默认值，桌面、系统预览都传入存储的设置。
