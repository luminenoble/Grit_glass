# 项目概览

Grit Glass 的现行结构，对应 1.1.1.2（2026-11-17）。构建与发布见 [开发与发布.md](开发与发布.md)。改动这里描述的内容时，在同一个提交里更新本文。

## 1. 应用

纯待办应用，从 Grhinet 6.2.4 分出，去掉了 Rhine 场景和插图；Grhinet 本身在 [luminenoble/Grit](https://github.com/luminenoble/Grit) 单独维护。两者都基于上游 [Grit](https://github.com/shub39/Grit)（GPL-3.0）。

- 显示名 Grit Glass，`applicationId` 为 `io.github.luminenoble.gritglass`，可与 Grhinet 同时安装。Kotlin 包名和文件路径与 Grhinet 保持一致，方便两个仓库互相 `cherry-pick` 共用部分的修复（本仓库的 `grhinet` remote 指向 Grhinet）。
- 两个端：**Android 手机**（随身执行：Task 页、提醒、小组件）和 **Windows 桌面**（`:desktopApp`，规划：宽屏的自由任务墙，第 7 节）。两端共用 `:shared:ui` 的全部界面，数据各存一份，用局域网同步整库互传（第 8 节）。
- 导航：**Task / Overview / Setting**（窄屏为底部胶囊，宽屏为左侧导航栏）。Task 是类别与任务列表，Overview（下文称总览）在宽窗口是任务墙、以后再说和已完成三个视图，在手机上是临期清单、以后再说和已完成（第 4 节）。
- 界面文案全部是英文。本仓库新增的文案直接写在代码里，不进 `strings.xml`；语言设置只影响上游带翻译的那部分条目。下文在引号里写的是界面上的原文。
- 已从上游移除且不恢复：Habit、统计栏目、AI 任务分解、动态取色与整体调色、深色主题。

| 项目 | 现状 |
| --- | --- |
| 语言 / UI | Kotlin 2.4、Compose Multiplatform 1.11.1、Material3 Expressive |
| 模块 | `:androidApp`（Room、DataStore、Glance 小组件、平台实现）、`:desktopApp`（Windows 桌面端，Kotlin/JVM + Compose Desktop）、`:shared:core`（模型、接口、纯函数、`SnapshotTaskRepo`）、`:shared:ui`（commonMain UI）、`:shared:sync`（Kotlin/JVM，Android 与桌面共用：局域网客户端、回滚快照与任务墙布局的文件存储）、`:webDemo`（JVM / Wasm 演示桩，需保持可编译） |
| 桌面 | JDK 21+，Windows 10/11 x64（第 7 节） |
| Android | minSdk 29、target / compile 37 |
| 主题 | 固定米色浅色主题 + 液态玻璃控件（见第 5 节） |

## 2. 数据

以 `Category → Task → Section` 组织。

| 对象 | 主要字段 |
| --- | --- |
| Category | `name`、`description`、`orderIndex`、`titleColor`、`createdAt/updatedAt` |
| Task | `categoryId`、`title`、`description`、`orderIndex`、`titleColor`、`isCompleted`（手动）、`isToday`、`reminder`、`deadline`（DDL，按天，可空）、`priority`（`LOW` / `NORMAL` / `HIGH`，存为 0 / 1 / 2，默认 `NORMAL`）、`lastTouchedAt`、`completedAt`、`hiddenUntil`（挂起到哪天）、`isSomeday`（以后再说）、时间戳 |
| Section | `taskId`、`title`（空则为 `unname`）、`content`、`orderIndex`、`isCompleted`、`titleColor`、时间戳 |

规则：

- ID 固定，不随排序改变；`orderIndex` 在同一父级内从 0 连续；新增一律尾插；移动和删除在事务内补齐排序。
- Section 的完成是布尔值，不记日期。Task 与 Section 的完成互不影响。已完成 Task 不触发提醒，重新打开时只恢复仍在未来的提醒。
- **完成即归档**：Task 完成时仓库写入 `completedAt`，取消完成时清空。归档的任务保留原来的 `orderIndex`，Task 页、任务墙和小组件只是跳过它，取消完成后回到原类别的原位置。
- **在场**（`Task.isActive`）：未完成、不是“以后再说”、`hiddenUntil` 不在未来。只有在场的任务出现在 Task 页（包括 Today）和任务墙上。挂起的任务到 `hiddenUntil` 当天自动回来；“以后再说”不带日期，要手动放回。
- **动过**（`touches`）：修改标题、内容、Section（包括勾选）、DDL、优先级，或加入 Today，仓库就把 `lastTouchedAt` 更新为当前时间。只打开查看、排序、完成、挂起、改颜色不算。
- **Today 每日清零**：每次显示 app 时，如果日期比 DataStore 里记的 `last_opened_on` 新，就清掉所有任务的 `isToday`（`clearToday`）。不算“动过”，不计数，也不标逾期。
- **颜色** `titleColor`：null 为默认（`onSurface` `#3C3A36`）；`#RRGGBB` 为纯色；2–5 个以逗号分隔为从左到右的渐变（如 `#C0392B,#1E6FD9`）。仓库写入、备份导入都校验格式（`shared/core/.../tasks/TaskRules.kt`）。存储原值不变，渲染文字时对过浅颜色做线性 RGB 感知亮度钳制（`ensureReadableOnPaper`），保证在暖米纸面上的可读性；色卡点与边框仍显示原色。

**数据库** `grit_glass_database`，Room，`SCHEMA_VERSION = 2`（`androidApp/.../tasks/data/database/`）：`categories`、`tasks`、`sections` 三表，外键级联。1 → 2 是手写迁移 `Migration1To2`（`Migrations.kt`），因为要转换已有的值：三张表各自重建后改名到位；`priority` 全部为 `NORMAL`，`lastTouchedAt` 取 `updatedAt`，已完成任务的 `completedAt` 取 `updatedAt`，Section 的 `completedOn != null` 记为已完成，Category 去掉 `hideCompleted`。schema 变化时提高版本并加迁移（见开发与发布）。

**桌面端存储**：不用 Room，整库就是一份 `TaskBackup` v2 JSON（`%APPDATA%\GritGlass\tasks.json`），由 `SnapshotTaskRepo`（`shared/core/.../tasks/SnapshotTaskRepo.kt`）在内存中维护，规则与 Android 仓库相同（连续排序、尾插、`touches`、完成即归档）。每次写入先把新版本交给持久化（先写临时文件再原子替换），成功后才生效，失败时整次修改不生效。启动时读不懂的文件会被改名为 `tasks.unreadable-<时间>.json` 放在一旁，不会被覆盖。web 演示用同一个类，只存在内存里。

**备份**：`TaskBackup`（`shared/core/.../settings/backup/TaskBackup.kt`），JSON 中 `format = "grit_glass"`、`formatVersion = 2`，包含上表的全部字段，Section 嵌套在 Task 内。导入同时接受旧的 `grit_rhine` 版本 1（Grit Glass 1.0.x 和 Grhinet 导出的文件），先按数据库迁移的同一套规则改写成版本 2 再校验。Grhinet 不能导入 Grit Glass 的备份，两个仓库的备份代码分开维护。导入先校验（ID、引用、颜色、日期、连续排序）、展示数量，确认后在一个事务内整库替换；失败不改动现有数据。备份不含本机设置，也不含任务墙上卡片的位置。

## 3. Task 页与 Setting

- Task 页：顶栏（切换完成状态、调整顺序，副标题为正文字体常规字重 + `SecondaryText`）、类别托盘（今天、各类别、新增 / 编辑类别；芯片文字统一使用 `onSurface` / `SecondaryText`，仅左侧 10 dp 彩色圆点表示类别色）、任务卡列表、右下角添加任务。只列在场的任务（第 2 节）；任务卡在标题下显示 DDL，标题关闭 Android 多余上下留白，描述与展开后的 Section 单行省略号截断，`"X/Y Section"` 为 `labelMedium` + `SecondaryText`。
- 勾选完成后任务立即离开列表，浮动按钮 / 功能键上方出现玻璃提示“Archived · Undo”（`bottom = LocalFloatingBarInset + GlassMetrics.Primary + 24 dp`），停留 5 秒（`ArchiveToast`，Task 页和总览共用）。
- **切换完成状态**（顶栏“调整顺序”左边的对勾圆圈图标）：打开时每张任务卡右侧出现圆圈，点按任务卡即完成并归档；关闭时点按任务卡不做任何事，只能滚动列表，防止滑动时误触完成。它与“调整顺序”互斥（打开一个会关掉另一个），切换类别时两者都关闭。宽屏布局里每个类别面板的“调整顺序”旁各有一个，只管本面板。左侧详情按钮进入编辑，不受影响；长按拖动排序不变。
- 任务详情、新建任务、类别编辑是整页编辑器，用一份草稿，保存时整体提交，返回时有未保存提示。任务编辑器里有 Deadline（按天选，可清除）、Priority（Low / Normal / High）、Suspend（Tomorrow、Monday、In a month、Pick a day）和 Later。Section 列表有“调整顺序”切换：默认右侧为编辑图标，调整时为拖动手柄，也可输入目标序号。
- 颜色选择 `ColorPickerDialog`：纯色 / 渐变（至多 5 色）、色环与亮度、R/G/B 与 HEX 输入、复制粘贴（同时写入应用内与系统剪贴板，粘贴优先读系统剪贴板）。Category、Task、Section 表单共用 `TitleColorRow`。
- Setting：通知、小组件字号、启动页面（Task / Overview / Setting）、24 小时制、任务墙（见下）、外观（`flexFontEmphasis()` 顶栏标题、“降低透明度”、`GlassGroup` 整行可点字体列表）、备份（含 LAN Sync，第 8 节）、关于、更新内容、语言。只有手机有的项目（Grit Plus、检查更新、通知、小组件字号）在桌面端不显示（`hasPhoneFeatures`）。
- 任务墙设置 `WallSettings`：“Deadline steps”三个天数阈值 a / b / c（Due / Soon / Upcoming，正整数，必须 a < b < c，默认 1 / 7 / 30，不合法的输入不保存），决定桌面卡片纸色的深浅和手机临期清单的分组；“Card text size”卡片字号（小 / 中 / 大）；“Show priority with”只作用于临期 / 以后再说 / 已完成的列表卡片（“Title & border”或“With background”），任务墙上重要度就是卡片大小。

## 4. 总览

代码：`shared/core/.../tasks/Wall.kt`（紧迫度、卡片尺寸、排序、落位与整理，纯函数）、`shared/ui/.../overview/`（`OverviewScreen`、`Desk`（任务墙）、`TaskTile`（列表卡片）、`Paper`（纸面海拔与纸色）、`TaskLens`、`CardTapKeys`）。

页内右上角的分段切换视图。窗口宽度不是 Compact（≥ 600 dp，桌面端和平板）时为 **Wall / Later / Done**，默认任务墙；手机上为 **Due / Later / Done**，不再承载卡片墙。下面的类别托盘可以只看一个类别。

**紧迫度**（`urgency`）：剩余天数 = `deadline` − 今天，按绝对天数划分，一天之内不会跳动。阈值 a / b / c 来自设置。

| 紧迫度 | 条件 | 纸色 |
| --- | --- | --- |
| `NONE` | 没有 DDL | 亮米纸 `#FBF8F3` |
| `AHEAD` | 剩余 > c 天 | 极淡暖调 `#F8F1E6` |
| `UPCOMING` | 剩余 b+1 到 c 天 | 浅暖沙 `#F3E7D3` |
| `SOON` | 剩余 a+1 到 b 天 | 琥珀浅染 `#F0DCBC` |
| `DUE` | 剩余 ≤ a 天或已过期 | 焦糖浅染 `#EACBA9`，左侧 3 dp 墨色标记（已过期为砖红 `#9A3B30`） |

深色文字在这几种纸色上都远高于 4.5:1。

### 4.1 任务墙（宽窗口）

一张可平移缩放的暖米纸桌面，在场的任务像便签一样散落在上面。**大小是重要度，深浅是 DDL 紧迫度。**

- **卡片尺寸**（`cardSize`）：`HIGH` 或已过期 300 × 150 dp（类别、标题、描述摘要、日期、Section 进度）；`NORMAL`，或加入 Today 的 `LOW`，230 × 112 dp；`LOW` 180 × 92 dp。窗口再宽也不截断成小格。
- **卡片**（`DeskCard`）：纸色按上表；顶部中间一段半透明“胶带”是类别色（渐变照画，无类别色为素色胶带），中大卡片左上角带类别圆点和名称；标题用任务自己的颜色（经亮度钳制），`HIGH` 加粗。底部写日期与剩余天数（“Nov 22 · 5 days”），没有 DDL 的写距上次动过多久（“Idle 12 days”“Touched today”），再加 Section 进度和 Today 小太阳。外侧暖褐柔影、左上亮白受光边与底部微暗收口边（`paperElevation`，`HIGH` 抬升更明显）；沉底卡片改为内凹。已过期卡片底部直接给 New date / No date / Give up 三个选择。
- **沉底**（`hasSunk`）：没有 DDL 的任务，`LOW` 超过 30 天、`NORMAL` 超过 60 天没动时，卡片做内凹质感：移除外阴影、换成深米底色 `#E3DCCE` 并带顶部内侧细暗影；落位和整理时排在最外圈。预览里问一句“Untouched for N days. Still worth doing?”，给三个选择：Make it smaller（进编辑器）、Later、Give up。可以不理会。`HIGH` 永不沉底。
- **自然微倾**：每张卡片带 ±1.5°–2.5° 的倾角（按任务 ID 固定）。鼠标悬停时平滑回正到 0°、略放大并加深投影，右上角出现编辑按钮。
- **操作**：左键拖动卡片自由摆放；单击做功能键选定的事（默认胀开预览），长按做另一件，双击或悬停时的编辑按钮进入整页编辑器。在空白处拖动、按住中键拖动或滚轮平移（Shift + 滚轮横向）；Ctrl + 滚轮或双指捏合以光标为中心缩放（35%–180%）。背景有随桌面移动的淡点阵。
- **坐标只存本机**（`CardSpot`：中心 x / y（dp）与倾角，以任务 ID 为键，`WallLayoutStore`）：桌面端 `%APPDATA%\GritGlass\wall_layout.json`，Android 平板 `files/wall_layout.json`。不进备份，不参与同步。
- **落位**（`placeMissing`）：没有坐标的任务（新建的、同步过来的）按 `wallRank`（紧迫度 → 优先级 → DDL 早晚 / 最近动过 → ID）依次在向日葵螺旋上找离中心最近、与已有卡片相距 20 dp 以上的空位；已有坐标的卡片不动。落位考虑全部在场任务，所以筛选类别时新卡片也不会压在隐藏的卡片上。已删除和已完成任务的坐标在任务加载后清掉（挂起和以后再说的保留，回来时还在原处）。
- **整理**（左下角玻璃工具条）：**Scatter** 随机松散重排（间距更大、轻微错位、随机倾角）；**By category** 每个类别一团，按类别顺序从左到右成行；**Urgent to centre** 紧迫与重要的卡片排到中心。整理后 8 秒内可 **Undo**。工具条右侧是缩小、当前比例（点按回到 100%）、放大和 **Fit**（取景到全部卡片）。首次进入时自动 Fit。

### 4.2 临期清单（手机）

“Due”列出在场且有 DDL 的任务（`dueOrder`：DDL 从早到晚 → 优先级 → ID），按紧迫度分组：Passed、Within a 天、Within b 天、Within c 天、Later dates。卡片为一行的列表卡片（`TaskTile`），纸色与任务墙相同，已过期的带砖红标记；没有 DDL 的任务只在 Task 页。

### 4.3 两个功能键与预览

- **功能键**（`CardTapKeys`）：浮在卡片上方右下角的玻璃胶囊，做法与导航胶囊相同（选中的是抬起的透镜并展开名字）。它决定点按卡片做什么：**Preview**（预览，默认）或 **Details**（进入整页编辑器）。长按卡片做另一件事。三个视图共用这个选择。
- **预览**（`TaskLens`）：一片玻璃从卡片所在的位置胀开，盖在墙上，其余部分被一层 0.42 的纸面色压淡。它画在页面里而不是 `Dialog` 窗口里，所以能真的采样墙面：`Regular` 档，底色减到 0.48，卡片的颜色在玻璃后面化成一团团光晕。点玻璃外面、按返回或在桌面端按 Esc 收起。
- 预览里不进编辑器就能做的事：勾选 Section、Complete、Suspend（Tomorrow / Monday / In a month / Pick a day）、转入 Later，以及对过期和沉底任务的那三个选择。已完成的任务给“Reopen”，以后再说的给“Back to the wall”，挂起中的给“Bring back now”。成排的选择用 `FlowRow`，放不下就换行。

### 4.4 以后再说、已完成

两个视图（以及临期清单）都用一行高 48 dp 的列表卡片 `TaskTile`，每行 2 张（宽屏 4 张）。类别色做边框（`HIGH` 2.5 dp，其余 1.5 dp），按优先级向纸面减淡（`HIGH` 不减淡、`NORMAL` 48%、`LOW` 68%），设置选“With background”时底色再用类别色淡染（0.34 / 0.10 / 0.04）。

- **以后再说**（Later）：分“Later”（按 `lastTouchedAt` 从近到远）和“Suspended”（按回来的日期从早到晚，卡片上写日期）两组。
- **已完成**（Done）：全部归档任务按 `completedAt` 从新到旧，卡片上写完成日期。右上角“Delete completed”作用于全部归档任务，需要二次确认。
- 日期写成“Nov 23”，不在今年时带年份（“Jan 15, 2027”）。

## 5. 液态玻璃

代码：`shared/ui/.../theme/LiquidGlass.kt`（材质、尺寸、采样）、`theme/GlassPress.kt`（按压）、`androidMain/.../theme/GlassLens.android.kt` 与 `jvmMain/.../theme/GlassLens.jvm.kt`（透镜着色器）、`components/glass/GlassComponents.kt`（按钮、开关、分段等）。

**原则**：玻璃只用于浮在内容上的控件；任务卡、设置行是不透明的纸面（`Content` 档）。玻璃靠光来成形：透镜边、高光边、形状外侧的暖褐阴影，底色很淡。按下时被光照亮，任何时候都不变暗。主题 `GritBaseColors` 显式定义暖调 `error`（`#9A3B30`，与 `GlassTokens.Danger` 一致）及容器色；图标底托与按钮统一为纯粹圆形/胶囊，不用异形或按压形变。`GritRadius`、`GlassShapes`、`ListItemExt` 共用同一套圆角尺度（单行卡片 `12 dp`、双行/常规卡片 `16 dp`、28 dp 容器内 8 dp 留白对应 `20 dp`、28 dp 弹窗内 16 dp 留白对应 `12 dp`、`GlassToolbar` 为 `28 dp = 22 dp + 6 dp`）；`GlassSegmented` 在窄空间回退到紧凑水平边距并对超长文案用省略号截断。

| 档位 | 用途 | 底色（有采样 / 无采样） | 模糊 | 透镜边带 | 色散 |
| --- | --- | --- | --- | --- | --- |
| `Thin` | 导航胶囊、添加任务、图标按钮、类别芯片与托盘、分段、提示 | `#FBF8F3` 0.08 / 0.36 | 1.5 dp | 14 dp | 0.35 |
| `Regular` | 菜单、滚动后的顶栏、任务预览 | `#FBF8F3` 0.55 / 0.82 | 18 dp | 10 dp | 0 |
| `Thick` | 对话框、底部表单 | `#F2EDE5` 0.82 / 0.95 | 30 dp | 无 | 0 |
| `Content` | 任务卡、设置分组行 | 不透明 | 无 | 无 | 0 |

- 一个玻璃面由下到上：形状外侧的暖褐 `#5B4B3A` 阴影（模糊后裁掉形状内部，所以不会从下面把玻璃染灰）→ 背景采样（先模糊，再过透镜）→ 底色 → 顶部光泽 → 底部内侧聚光 → 左上最亮的高光边 → 外细线。
- **透镜**（Android 13+，AGSL `RuntimeShader`）：参考 Apple Liquid Glass 和 Kyant 的 AndroidLiquidGlass。用圆角矩形 SDF 求到边缘的距离，在宽 `bevel` 的边带里，玻璃表面按四分之一圆下落，采样点沿法线向内偏移 `bend·(1−√(1−x²))`（x 在边缘为 1，`bend = 1.25·bevel`）；红、蓝通道分别多 / 少偏移 `dispersion` 倍做色散；整体饱和度 ×1.25；边带按下落量提亮 0.22。着色器只编译一次，所有玻璃共用。桌面端把同一段着色器作为 Skia SkSL（`RuntimeEffect` + `ImageFilter.makeRuntimeShader`，先模糊再折射）使用；编译失败时退回纯模糊。
- Android 12 只有模糊没有透镜；Android 10–11、“降低透明度”（全部不透明）、独立窗口（`Dialog`、`Popup`、`ModalBottomSheet` 采样不到主窗口）都不采样，用无采样底色；Android 12 以下阴影改用平台阴影。
- **采样源**：`Modifier.glassSource` 每次绘制把内容记录进图层，采样它的玻璃不能画在它里面。紧凑布局里整个 `NavDisplay` 是导航胶囊的源，任务列表的 `Column` 是添加任务按钮的源，总览页的 `Column` 是功能键、任务墙工具条和任务预览的源。顶栏按钮和类别托盘在源内部，不采样。大片的 `Regular` 玻璃要求源把纸面背景也记录进去（`background` 写在 `glassSource` 之后）：否则记录下来的只有内容，模糊后是半透明的，下面清晰的内容会从玻璃里透出来。
- **浮动层**：紧凑布局里导航胶囊浮在页面上，测得的高度经 `LocalFloatingBarInset` 提供。任务列表、设置各页、整页编辑器把它加进底部内边距，内容可以一直滚到胶囊下面；添加任务按钮和总览的功能键放在它上方 16 dp。
- **尺寸** `GlassMetrics`：所有控件（图标按钮、文字按钮、类别芯片、导航项）高 44 dp，主操作 56 dp，托盘内边距 6 dp，图标 22 dp。
- **按压**：不用灰色状态层。`GlassPressIndication` 是全局 `LocalIndication`，从手指处向外泛光（90 ms 亮起、360 ms 退去），光在文字和图标下面；玻璃控件同时放大到 1.06。Material 组件自带的涟漪改为白色（`GlassRipple`）。键盘焦点显示为墨色描边。
- **状态**：选中（导航项、类别芯片、分段、打开的切换按钮）和主按钮 `Prominent` 是更亮更密的透镜 `#FFFDF9` 0.62，文字加粗，仍然透光；`Danger` 是透明玻璃配 `#9A3B30` 文字；开关打开为橄榄色 `#66704F`。
- 托盘里的图标按钮不单独成片（`inTray`），与未选中的芯片一样平放；单独的图标按钮是透明玻璃圆片。
- 玻璃上的次要文字用 `#57534B`，不要用 `mutedText #8C857A`（对比度不足）。

## 6. 小组件

Glance 任务小组件（RemoteViews，无法真模糊桌面）。背景和条目是 `layer-list` drawable（`widget_glass_bg`、`widget_glass_item(_done)`）模拟玻璃。

- 只显示未完成的任务，与归档一致。
- 每条任务是自有布局 `widget_task_row`：只有标题（一个带玻璃背景的 `TextView`），不显示步骤（Section）数，以 `AndroidRemoteViews` 整条嵌入，点击切换完成。不要把 `AndroidRemoteViews` 放进 Glance 带背景的容器里：Glance 会把它插到背景那一层，并丢掉同一容器里的其他子项。
- 桌面会把一条任务的视图复用给另一条任务，旧视图上设过的属性会留下来。所以每次绑定都要设全背景、内边距、字号、颜色和文字，不能只给部分任务设置某个属性（例如只在有步骤时显示一行），否则别的任务会带出上一条的内容和字号。
- Task 标题按存储的颜色显示，渐变也一样。Glance 的文字不支持渐变画笔，所以标题是 `TextView`，每个字带自己的 `ForegroundColorSpan`：按小组件实际宽度用 `StaticLayout` 排版（最多两行），取每个字的水平中点在最宽一行中的位置，在等距色标间插值（`widgets/WidgetTitleGradient.kt`）。效果与 Task 页横跨标题的渐变一致，只是逐字而非逐像素。
- 字号取自应用内设置（小 / 中 / 大），类别名与任务标题同号。在第一帧之前读出；不能以默认值起步，否则每次小组件会话开始都会先按“中”画一遍再跳到所选字号。`Content` 的字号参数没有默认值，桌面、系统预览都传入存储的设置。

## 7. Windows 桌面端

代码：`desktopApp/src/main/kotlin/com/shub39/grit/desktop/`。界面就是 `:shared:ui` 的 `MainApp`，窗口足够宽时走宽屏布局（左侧导航栏、Task 页多面板、总览的任务墙）。

- **数据目录** `%APPDATA%\GritGlass\`（非 Windows 为 `$XDG_DATA_HOME/GritGlass` 或 `~/.local/share/GritGlass`；环境变量 `GRIT_GLASS_HOME` 可改到别处）：`tasks.json`（整库，第 2 节）、`settings.json`（本机设置与窗口位置大小）、`wall_layout.json`（卡片坐标）、`rollback/`（回滚快照，第 8 节）。
- **设置**：与手机同一套设置接口（`DesktopSettings`、`DesktopTheme`），存在 `settings.json`。默认启动页为 Overview、24 小时制。没有提醒（`NoAlarms`，任务的提醒时间保留给手机）、没有生物识别和小组件，全部功能免费。
- **窗口**：记住大小、位置和是否最大化，最小 760 × 560。快捷键：**Ctrl+N** 在当前类别新建任务（会先切到 Task 页），**Esc** 相当于 Android 的返回（`DesktopBack` 交给最近显示的 `DraftBackHandler`：收起任务预览、关闭整页编辑器并照常询问未保存的修改）。
- **字体**：装有 Maple Mono NL NF CN（`%WINDIR%\Fonts` 或用户字体目录下的 `MapleMonoNL-NF-CN-Regular/Bold.ttf`）时，全部文字（含 `flexFontEmphasis` 标题，用 Bold）都用它，中英文同一套字形，避免中文逐字回退到系统字体造成粗细不一；此时外观页的字体选择在桌面端不起作用。没装则用应用自带字体（`platformFontFamily`）。
- **备份**：导出 / 导入走 FileKit，弹出 Windows 原生文件对话框，格式与手机相同。
- **更新内容**：打包时带上 Android 的 `changelog.json`，首次打开新版本时同样弹出。

## 8. 局域网同步（LAN Sync）

代码：协议与接口 `shared/core/.../sync/LanSync.kt`；手机客户端与文件存储 `shared/sync/`；桌面服务端 `desktopApp/.../DesktopLanSync.kt`；页面 `shared/ui/.../setting/ui/section/LanSyncPage.kt` 与 `LanSyncViewModel`。入口为 Setting → Backup → LAN Sync，web 演示没有。

一端的整库替换另一端的整库，与导入备份相同：完全复用 `TaskBackup` v2 和 `replaceData`，不做合并。本机设置、任务墙坐标留在各自设备上。

- **桌面端（服务）**：点“Turn on LAN Sync”后，用 JDK 自带的 `com.sun.net.httpserver.HttpServer` 在随机端口监听，生成一次性 6 位 PIN，显示二维码、本机局域网 IPv4 地址（只取启用中的真实网卡的私有地址，192.168.x 优先，跳过 vEthernet / WSL / VMware 等虚拟网卡）、端口和 PIN，并列出本次会话中手机做过的事。离开页面、关闭窗口、10 分钟没有请求、或累计 5 次 PIN 错误时停止监听（后两种在页面上说明原因，重新打开即换新 PIN）。只接受来自私有 / 链路本地 / 回环地址的请求，请求体上限 32 MB。
- **接口**：每个请求带 `Authorization: Bearer <PIN>` 与 `X-Grit-Device: <设备名>`。`GET /snapshot/meta` 返回 `SnapshotMeta`（设备名、导出时间、最近修改时间 = 所有 Category / Task / Section 的 `updatedAt` 最大值、类别 / 任务 / Section 数）；`GET /snapshot` 返回整库 JSON；`POST /snapshot` 上传整库，桌面端先 `TaskBackup.decode` 校验，再保存回滚快照、`replaceData`，返回替换后的 meta。校验失败返回 400，桌面数据不变。
- **配对链接**：二维码内容为 `gritglass://sync?host=<地址,地址>&port=<端口>&pin=<PIN>`（`LanPairing`）。Android 的 `MainActivity` 注册了这个链接（`singleTop`），用相机或扫码应用打开后直接进入 LAN Sync 并填好、自动连接；也可以手动输入地址、端口和 PIN。多个地址依次尝试（连接超时 4 秒）。
- **手机端（客户端）**：`ClientLanSync` / `LanClient` 用 `HttpURLConnection` 走明文 HTTP（`network_security_config.xml` 因此允许明文；应用其余网络请求都是 HTTPS）。连接后并排显示两端的最近修改时间（较新的一侧标“newer”）、类别数、任务数和 Section 数，由用户明确选择 **Push to <桌面>**（手机覆盖电脑）或 **Pull from <桌面>**（电脑覆盖手机），都要二次确认。连接失败、PIN 错误、数据不合法都给出原因，不改动数据。
- **回滚快照**（`RollbackStore`，`FileRollbackStore`）：任何一端的数据被替换之前（Pull、对方 Push、从快照恢复），先把当前整库存成 `rollback/<毫秒时间戳>.json`（附原因），只保留最近 5 份。手机在 `files/rollback/`，桌面在 `%APPDATA%\GritGlass\rollback\`。LAN Sync 页底部列出快照（时间、原因、数量），可以恢复；恢复前同样先存一份当前数据。列表不做校验，所以快照不会因为数据不合规而消失；恢复时才校验，不通过就说明原因、不改动数据。
